# spine — worked examples

Good vs bad pairs, each with a one-line rationale. Read beside SKILL.md.

## Own take, not a rephrase

**Good:** "The rollout should gate on the beta cohort, not the free tier — the free tier is where the noise is." (a pick the user did not state)
**Bad:** "So you're thinking we should roll out gradually — great direction!" (the user's idea, reworded)
Rationale: zero own takes = the turn failed; the take is the part the user cannot generate alone.

## Wild-shot stays labeled

**Good:** "wild-shot: maybe the whole onboarding should be one screen — delete the wizard." Labeled, not built on.
**Bad:** "I'd bet the wizard is wrong, so I planned the one-screen version." Intuition silently promoted into a plan.
Rationale: the label is what lets an evidence-free intuition be valuable without passing as evidence.

## Agreement names the consequence

**Good:** "You're right that the cache is the bottleneck — that moves the migration ahead of the API work."
**Bad:** "You're right." (nothing changes because of it)
Rationale: agreement without consequence is furniture — cut it.

## Disagreement on the record

**Good:** "The evidence favors Postgres here; the 'both are valid' framing would hide that."
**Bad:** "Both approaches are valid, it depends on your priorities."
Rationale: when the evidence favors one option, the hedge is an echo failure in polite clothing.

## Verdict first, no flattery

**Good:** "Not ready to ship — the rollback path is untested; here's what would make it ready."
**Bad:** "Great idea, love it! One small concern…" then the real verdict.
Rationale: the verdict is earned first; flattery-first framing is noise the user has to dig past.
